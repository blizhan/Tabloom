# Feature Specification: Common View Runtime

**Feature Branch**: `main`（当前分支；本次未创建功能分支）

**Created**: 2026-09-17

**Status**: Draft

**Input**: 将已评审并补全的 [Common View Runtime 设计](../../docs/superpowers/specs/2026-09-17-common-view-runtime-design.md) 转化为需求规格：用户可以在浏览器中用自己的数值数据建立预测上下文、重复运行情景预测、保存并恢复上下文，再将准确对应原始数据行的结果用于查询分析；通用工作台和预配置案例共享这些行为。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用自己的数据完成预测与查询闭环 (Priority: P1)

分析人员在 Common View 中指定训练数据、数值特征、目标列和待预测数据，使用默认模型得到预测均值，并将结果与输入数据关联后继续查询。数据和预测计算留在浏览器内。

**Why this priority**: 这是通用工作台的最小核心价值，也是其他复用和情景能力的基础。

**Independent Test**: 使用固定的小型数值回归数据集，完成训练准备、预测、结果关联和查询；不依赖案例界面或远端推理服务。

**Acceptance Scenarios**:

1. **Given** 支持范围内的训练和预测数据，**When** 用户选择目标列并运行默认模型，**Then** 每个预测输入行得到一个有限的预测均值，结果记录模型、数据和本次运行身份，并可继续查询。
2. **Given** 输入含重复业务键且查询顺序发生变化，**When** 用户查看预测与原始输入的关联，**Then** 每个预测仍对应本次实际使用的那一行，不依赖重新查询后的顺序或业务键唯一性。
3. **Given** 训练目标缺失、特征顺序不匹配或数据超出支持范围，**When** 用户运行预测，**Then** 系统指出具体原因，不隐式删行、换列、抽样或改变模型。
4. **Given** 模型和输入已就绪，**When** 用户运行预测，**Then** 无需安装本地预测环境或向远端推理服务上传数据即可完成闭环。

---

### User Story 2 - 修改情景并只查看最新预测 (Priority: P1)

案例使用者或分析人员修改待预测数据中的数值，重复比较情景与基准结果，无需重新准备未改变的训练上下文。快速连续修改时，当前展示始终对应最新请求。

**Why this priority**: 可重复的情景探索是该项目区别于一次性预测工具的核心体验。

**Independent Test**: 从一个已准备好的上下文和基准输入开始，连续提交不同情景，检查训练准备次数、结果身份和当前结果，独立于上下文持久保存能力。

**Acceptance Scenarios**:

1. **Given** 训练数据和配置未变，**When** 用户只修改预测输入，**Then** 复用训练上下文，生成与新情景对应的独立结果，并保留基准输入和基准结果。
2. **Given** 用户快速提交 A、B、C 三次修改且旧请求较晚完成，**When** 请求完成，**Then** 只有 C 能成为该情景当前结果，A/B 不覆盖 C；被取消的请求有明确状态。
3. **Given** 用户明确保存了两个独立实验，**When** 两者运行，**Then** 不因交互请求合并而丢弃其中任一实验。
4. **Given** 正在运行预测，**When** 用户关闭该运行环境，**Then** 不再接受新工作，未开始的请求被取消，运行中的工作结束后资源被释放，迟到结果不被发布。

---

### User Story 3 - 保存并恢复可复现的预测上下文 (Priority: P2)

分析人员在同一浏览器中再次打开项目时，复用已下载的模型和已保存的训练上下文；当训练数据或模型配置发生变化时，系统明确重新准备上下文。

**Why this priority**: 避免重复下载和训练准备，降低重复使用的等待和资源开销，同时防止使用过期结果。

**Independent Test**: 保存一个上下文，完全关闭运行环境后重新打开，使用相同输入预测并比较结果；再单独改变一个标签或模型版本验证失效。

**Acceptance Scenarios**:

1. **Given** 模型与上下文已完整保存且仍兼容，**When** 用户重新打开并运行相同预测，**Then** 不重复下载模型或重建训练上下文，结果满足同一准确性标准。
2. **Given** 已保存上下文，**When** 仅一个目标值、训练行顺序、特征顺序、随机种子、模型交付版本或数据处理规则版本发生变化，**Then** 旧上下文不被当作匹配项复用。
3. **Given** 缓存写入被中断或保存内容损坏，**When** 再次打开，**Then** 不使用不完整内容；可重新生成的缓存被重新准备，无法兼容的外部案例上下文则明确报错。
4. **Given** 浏览器无法持久保存新内容，**When** 本次运行仍可安全在内存中完成，**Then** 用户收到无法持久保存的说明，但仍能完成当前预测。

---

### User Story 4 - 从预配置案例进入通用工作台 (Priority: P2)

使用者打开预配置案例，从其已准备的上下文运行预测，并进入 Common View 检查相同数据、模型和情景。可用能力随模型和案例明确展示。

**Why this priority**: 让案例和通用工作台互通，并如实提供尚不能接受任意训练数据的模型能力。

**Independent Test**: 使用已发布的 TabICL v2 案例及其上下文运行预测，切换到工作台比较身份与结果，再尝试修改训练数据。

**Acceptance Scenarios**:

1. **Given** 兼容的已发布案例，**When** 用户打开并修改允许的情景输入，**Then** 无需重新建立训练上下文即可预测，结果按案例原始目标单位显示。
2. **Given** 案例已有数据、模型、上下文和结果，**When** 用户选择 Open in Common View，**Then** 这些身份和结果保持一致。
3. **Given** 使用初版 TabICL v2 案例，**When** 用户要求用另一份训练数据建立上下文，**Then** 系统明确说明该能力尚不支持，不静默换模型或继续使用原案例训练内容。
4. **Given** 案例上下文与模型版本不兼容，**When** 用户打开案例，**Then** 系统说明不兼容，不擅自改用其他训练数据重新训练。

### Edge Cases

- 空数据、列名重复、列长不一致、目标缺失或非有限值：在计算前拒绝，说明字段与原因。
- 数值特征缺失：按模型公开能力接收或拒绝；缺失值不得变成普通有效数值。
- 无限值默认拒绝；仅在模型支持且显式开启对应选项时接收。数值转换溢出始终拒绝，不能借此选项绕过。
- 分段或截取的数据、不同数值类型：保持逻辑行顺序与空值含义，无法准确识别的类型要求用户显式转换；不静默截断超出支持范围的整数。
- 特征数在数据处理后增加：按实际可接受的处理后规模校验，不能仅凭原始列数宣称支持。
- 硬件加速不可用或初始化失败：仅按事先允许的降级策略继续，并报告实际执行方式；运行中设备丢失则失败并允许显式重试。
- 预测数量与输入不符或输出非有限值：整次结果不发布，不产生部分成功表。
- 删除已保存缓存：不破坏仍在使用的上下文；已关闭或属于其他运行环境的上下文不能继续使用。
- 浏览器不能报告某类资源占用：报告“不可获取”，不将其显示为零或宣称已测得峰值。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在浏览器内支持单成员数值回归，从用户指定的训练特征和目标准备上下文，对指定预测行返回均值，并允许对结果继续查询；不得依赖远端推理服务或用户安装预测环境。验收：故事 1 场景 1、4。
- **FR-002**: 系统 MUST 默认提供 TabPFN 3.5 的用户数据上下文构建能力，并将初版 TabICL v2 限定为兼容的预构建案例；所有未支持的模型、任务及配置均显式拒绝。验收：故事 4 场景 1、3、4。
- **FR-003**: 系统 MUST 校验列身份、顺序、行数、目标有效性、数值范围和处理后的模型输入规模，按 Edge Cases 中的规则处理缺失与无限值，不隐式修复会改变训练或预测语义的问题。验收：故事 1 场景 3 及数据边界案例。
- **FR-004**: 系统 MUST 为每次预测保存实际输入的身份和逐行对应关系，保留原始业务键，并保证一个预测只关联到其实际输入行；输入重新查询、重排或重复业务键不得破坏关联。验收：故事 1 场景 2。
- **FR-005**: 系统 MUST 只发布完整且有效的结果，记录模型及交付版本、数据快照、目标、情景、上下文、本次请求、实际执行方式、运行版本和耗时。结果行数或数值校验失败时不得替换已有结果。验收：故事 1 场景 1 及结果异常案例。
- **FR-006**: 系统 MUST 使用训练阶段确定的数据处理规则转换预测输入并还原原始目标单位，不从预测数据重新拟合规则；数值结果符合 SC-002。验收：故事 1 场景 1、故事 4 场景 1 和准确性对照。
- **FR-007**: 系统 MUST 在训练内容和配置未变时复用上下文，仅修改预测输入或情景不得触发重新构建。验收：故事 2 场景 1。
- **FR-008**: 系统 MUST 根据实际训练特征和目标、有序结构、特征查询及参数、目标身份、随机种子、模型交付版本及数据处理规则版本判定复用；不能仅凭查询文本或数据源名称认为数据未变。验收：故事 3 场景 2。
- **FR-009**: 系统 MUST 支持完整上下文保存、校验及在重新打开后恢复，并区分持久保存内容与当前可用的运行上下文。恢复时必须验证兼容性；不兼容的执行环境不得直接复用。验收：故事 3 场景 1、3 及无效上下文案例。
- **FR-010**: 系统 MUST 复用已验证的模型下载内容，将同一模型的同时加载需求合并为一次下载，不把中断或损坏的保存内容当作命中。验收：故事 3 场景 1、3 及 SC-005。
- **FR-011**: 系统 MUST 在存储不足时明确说明持久保存失败；当前计算可安全继续时允许仅在本次运行中使用模型和上下文。验收：故事 3 场景 4。
- **FR-012**: 系统 MUST 对同一交互情景只保留正在执行与最新待执行的请求，过期结果不能成为当前展示或当前查询结果；显式独立实验不受该合并影响。验收：故事 2 场景 2、3。
- **FR-013**: 系统 MUST 在取消、关闭、加载失败和设备故障时提供明确状态，停止接收已关闭环境的新请求，并在相关计算结束后释放其资源；不得静默切换执行方式并重放失败请求。验收：故事 2 场景 4 和硬件异常案例。
- **FR-014**: 系统 MUST 公开模型能力、适用输入范围、加载和运行进度、实际执行方式及允许的降级结果；无法满足能力要求时提供可解释错误，不自动更换模型。验收：故事 1 场景 3、故事 4 场景 3 和硬件异常案例。
- **FR-015**: 系统 MUST 在 Case View 与 Common View 间保留同一数据、模型、上下文及结果身份，并保留案例的训练限制。验收：故事 4 场景 2、3。
- **FR-016**: 系统 MUST 让调用方在模型加载和运行期间仍可获得状态并请求取消，记录各阶段耗时和可获取的资源观测；无法获取的指标必须明确标注。验收：故事 2 场景 4 和资源观测案例。
- **FR-017**: 系统 MUST 保留基准和情景的独立输入、修改参数及结果；已有结果引用的输入不得在清理时消失，显式删除结果后允许清理不再引用的输入。验收：故事 2 场景 1 及删除后引用检查。

### Key Entities *(include if feature involves data)*

- **训练数据快照**：实际参与上下文准备的有序特征、目标及来源身份；数据内容和处理配置共同决定是否可复用上下文。
- **预测输入快照**：一次情景的实际输入及逐行身份，关联业务键、基准和修改参数；是结果回查的依据。
- **模型版本与能力**：选定模型、交付版本、可接受任务、输入限制及是否可构建新上下文。
- **训练上下文**：可供重复预测使用的训练结果与已确定的数据处理规则；具有来源、版本兼容性和运行有效期。
- **已保存上下文**：可供恢复的完整训练上下文，或绑定特定已发布案例的上下文；当前运行关闭不等于已保存内容被删除。
- **预测运行与结果**：请求身份、情景、输入、上下文、均值、模型与执行信息及成功/失败/取消状态。
- **案例**：预配置的数据、模型、上下文和允许的情景修改范围，可将同一实验带入通用工作台。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在支持范围的验收数据集上，用户可完整完成“选择训练和预测数据 → 获得预测 → 关联原始行 → 查询结果”；100% 预测行对应正确输入，重复业务键和重排测试中错误关联数为零。
- **SC-002**: 对既有默认模型的正常值、缺失值和显式允许无限值的完整参考数据集，所有最终预测均为有限值；参考交付版本最大绝对误差不超过 `0.0001`，节省下载体积的交付版本不超过 `0.002`（均为原始目标单位）。案例及其他模型在发布前固定各自目标单位误差预算，并对全部预测通过对照；不得将前述阈值泛化到任意目标量级。
- **SC-003**: 关闭并重新打开后，相同输入与兼容已保存上下文的预测仍满足同一准确性预算；相同训练条件下重新构建次数为零，逐项改变 FR-008 中语义因素的失效测试全部通过。
- **SC-004**: 连续 20 次情景修改的验收中，无论完成顺序如何，最终当前结果均来自第 20 次请求；过期请求覆盖当前结果次数为零，基准结果保持不变。
- **SC-005**: 同一模型的并发首次加载只产生一次模型内容下载；已完整保存且版本不变时重新打开的模型内容下载次数为零。损坏、中断和存储不足的验收场景均有明确结果且不发布错误预测。
- **SC-006**: 兼容预配置案例进入工作台后，数据、模型、上下文及已有预测身份全部一致；不支持的新训练请求全部得到明确拒绝，自动替换模型次数为零。
- **SC-007**: 连续 20 次准备、预测、关闭循环均完成，无已关闭上下文被再次使用、迟到结果发布或资源不足导致的失败；报告列明测试设备、数据规模、各阶段耗时、可观测资源及不可获取项，不将未观测指标作为通过证据。
- **SC-008**: 模型加载与运行中，状态可被读取且取消请求可被接收；取消、设备故障及执行方式不可用的验收场景全部返回明确状态，不静默重跑或修改已完成实验。

## Assumptions

- 本次指令承接刚完成的设计 review，以上述已补全设计为特性输入。设计文档继续承载具体实现方案，本规格约束用户可观察行为和验收结果。
- 本期交付共享预测能力及必要集成验证，不承诺最终界面、完整数据源管理、案例内容制作或全产品上线；故事中的界面操作可以先通过集成验证入口验收。
- 支持范围是单成员数值回归；分类、类别特征、多成员组合、TabPFN v3 以及 TabICL v2 任意训练数据的浏览器上下文构建均不在本期。
- 默认模型的初始验证范围为 3–1,024 个训练行、1–1,024 个预测行，以及处理后 1–32 个特征。实际原始特征限制取决于所选处理规则；案例模型遵循案例声明的固定训练及特征条件。
- 目标环境为已验证的桌面浏览器；无硬件加速时只在显式允许且已验证的方式下继续。移动设备性能、任意硬件性能和固定交互延迟不在本期保证范围。
- 首次模型下载需要网络，案例数据是否可离线取决于已有数据是否完整可用。本地保存可能被浏览器清理，不构成永久备份承诺；保存内容仅限当前浏览器，不引入账户或跨设备同步。
- 数值预算是拟定验收要求，不表示新实现已通过验证。依赖完整、可复现的官方参考输入/输出和处理状态；仅有历史误差摘要不足以验收。
- 模型及案例内容需有可访问、完整且版本固定的交付内容；发布所需授权沿用项目既有范围，本特性不新增权重分发授权。
- 当前项目 constitution 尚为未填写模板，不把示例原则视为已经采纳的项目约束。后续如制定正式原则，应检查本规格及实施计划的一致性。
