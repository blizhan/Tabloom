# Feature Specification: Phase 1 共享数据与实验闭环

**Feature Branch**: `main`（当前分支；本次未创建功能分支）

**Created**: 2026-09-20

**Status**: Draft

**Input**: User description: "roadmap.md 中的 Phase1，需要还包括准备一份数据，用于后续测试相关的功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用随附数据完成可检查的预测实验 (Priority: P1)

分析人员打开通用工作台，导入项目提供的数据，检查字段、类型、行数及基础统计，用 SQL 定义训练和预测数据，选择目标与可用模型，运行预测，再查询和导出结果。

**Why this priority**: 让用户可以从已知输入完成整个 Phase 1 主流程，也是后续功能测试的共同基线。

**Independent Test**: 使用随附数据和示例查询，在支持的桌面浏览器完成导入、检查、预测、结果查询与导出，无需案例页面或远端推理服务。

**Acceptance Scenarios**:

1. **Given** 随附数据包，**When** 用户导入正常样本，**Then** 工作台显示表名、字段、类型、行数、数值列的最小值/最大值/均值和各列空值数，均与数据包说明一致。
2. **Given** 已导入的表，**When** 用户执行示例训练和预测 SQL，**Then** 可预览各查询的字段和行数，选择目标及有序特征，且预测输入不包含目标真值。
3. **Given** 符合所选模型能力的输入，**When** 用户运行实验，**Then** 浏览器内生成预测表，每个预测准确对应实际输入行，随后可用 SQL 关联、过滤与汇总预测结果。
4. **Given** 查询后的预测结果，**When** 用户分别导出 CSV、Parquet 和 Arrow 并重新导入，**Then** 行数、行身份、空值和数值含义保持一致，且导出内容或随附说明保留数据版本、查询、模型及权重版本、目标、运行身份与耗时。

---

### User Story 2 - 使用自己的本地或远端数据 (Priority: P1)

分析人员添加自己的文件或可访问的远端数据，了解实际支持的连接能力，遇到不支持的来源时获得可执行的说明。

**Why this priority**: 验证工作台能够处理用户数据，而不只是运行内置演示。

**Independent Test**: 不加载模型，独立完成各数据入口的导入、预览和查询，并对受限来源检查提示。

**Acceptance Scenarios**:

1. **Given** 内容等价的本地 CSV、Parquet 和 Arrow 文件，**When** 分别导入，**Then** 使用明确的类型解释后，查询得到相同记录、空值含义和汇总结果。
2. **Given** 满足浏览器访问条件的 HTTPS 文件地址或 HTTP JSON/CSV 数据接口，**When** 添加来源，**Then** 可预览并查询其数据，记录实际取得的数据版本或内容身份；同等访问条件的预签名地址与对象存储地址适用相同规则。
3. **Given** 本地 DuckDB 数据库文件，**When** 用户尝试使用，**Then** 根据已验证能力明确显示打开、挂载、读取和写入各自的支持状态；受支持操作可检查表与查询数据，不支持的操作明确拒绝，测试不得修改原始文件。
4. **Given** 无法访问、超时、过期链接、跨域受限、所需分段读取不可用或格式损坏的来源，**When** 加载失败，**Then** 显示具体原因及重试或改用本地文件的建议，已成功导入的其他表仍可使用。

---

### User Story 3 - 理解运行状态并可靠地重复实验 (Priority: P2)

分析人员在下载、查询和预测时持续看到状态，能够操作页面，重新打开后复用可用缓存，并知道环境限制、失败原因和恢复方法。

**Why this priority**: 模型下载和计算可能耗时，明确状态与缓存行为决定工作台是否可重复使用。

**Independent Test**: 使用固定输入分别测试首次与再次运行、存储不可用、模型不受支持及执行失败，检查状态和结果保留。

**Acceptance Scenarios**:

1. **Given** 数据加载、长查询或模型运行正在进行，**When** 用户查看状态、切换面板或请求取消，**Then** 页面持续响应，显示所处阶段、可获取的进度、阶段耗时和资源观测；未知指标标注为不可获取。
2. **Given** 模型或任务不可用、输入超限或环境能力不足，**When** 用户选择或运行它，**Then** 展示限制及原因，不静默切换模型、删行、抽样或上传数据进行推理；允许的降级须事先明确并记录实际执行方式。
3. **Given** 数据和模型已完整缓存且版本未变，**When** 用户关闭后重新打开相同实验，**Then** 可复用缓存；远端来源更新只有在显式刷新并成功取得新内容后才产生新版本，旧实验仍指向原版本。
4. **Given** 缓存不完整、损坏或无法持久保存，**When** 用户再次运行，**Then** 系统不复用损坏内容，说明重新加载、重新选择文件或仅本次使用的恢复方式。
5. **Given** 已有成功结果，**When** 新查询、预测失败或取消，**Then** 不将部分或迟到结果替换成功结果，失败运行与旧结果的身份清楚区分。

---

### User Story 4 - 用固定数据验收后续功能 (Priority: P1)

开发者和测试者获得一份随项目交付的小型测试数据包，直接用于导入、SQL、特征选择、预测、缓存、导出及后续情景功能的回归测试，无需每次寻找或重新抓取数据。

**Why this priority**: 数据是本期明确要求的交付物；固定输入及预期结果使后续测试能定位行为变化。

**Independent Test**: 不依赖工作台和在线数据服务，按数据说明独立核对文件完整性、字段、时间切分、记录数、示例查询及预期汇总。

**Acceptance Scenarios**:

1. **Given** 干净的项目副本，**When** 测试者按说明打开数据包，**Then** 获得已准备好的样本文件、字段与单位说明、固定版本、来源及使用许可、校验值、示例查询和预期结果，无需账户、私有数据或在线抓取。
2. **Given** 正常样本，**When** 按示例查询切分训练与预测数据，**Then** 得到固定的 256 个训练行、32 个预测行和 4 个数值特征，训练时间严格早于预测时间，预测真值单独保存，特征均在所声明预测时点可用。
3. **Given** 同一正常样本的各格式副本，**When** 核对本地文件、远端文件和数据接口测试，**Then** 使用相同的字段语义与预期结果；远端入口可在受控测试环境提供，无需依赖第三方在线服务。
4. **Given** 随附异常变体和用例索引，**When** 测试者选择空数据、缺失目标、缺失特征、重复业务键、行重排、错误类型、非有限值或输入超限用例，**Then** 可找到对应输入及预期接受/拒绝行为；重复键与重排用例可检查结果逐行关联。
5. **Given** 固定模型交付版本及正常样本，**When** 后续测试对比预测，**Then** 使用数据包中独立参考得到的预测值、目标单位及明确误差预算判定，不以同一待测路径当次输出作为预期值。

### Edge Cases

- 同名表再次导入：要求选择新名称或明确确认替换，不悄悄覆盖已有实验的数据。
- 空文件、空查询结果、重复列名、无法解释的类型、缺失或非有限目标：在预测前指出问题，不隐式修复数据。
- 缺失特征按模型声明接收或拒绝；默认拒绝无限值，超限输入不得自动截断或抽样。
- SQL 语法错误或引用不存在的字段：显示错误位置或相关字段，保留编辑内容和上一份成功结果。
- 业务键重复、查询重排、导出后再导入：结果仍按实际输入行身份关联，不依赖业务键唯一。
- 预测行数不符或输出非有限：整次结果拒绝发布。
- 远端数据变化、浏览器清理缓存、容量不足：明确当前数据版本和不可恢复内容，不将新数据冒充旧实验输入。
- 取消、页面关闭或执行设备失效：明确状态，迟到结果不得成为当前结果，允许显式重试。
- 导出格式对类型的表达不同：明确类型解释方式；超出格式可无损表达的值必须提示，不能静默损失精度。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供通用工作台，让用户完成添加数据、检查表结构和统计、编辑并执行 SQL、预览数据、配置实验、运行预测和继续查询结果。验收：故事 1 场景 1–3。
- **FR-002**: 系统 MUST 支持本地 CSV/Parquet/Arrow、可访问的远端同类文件及 HTTP JSON/CSV 数据接口，保留来源与实际内容身份。验收：故事 2 场景 1、2。
- **FR-003**: 本期 MUST 对本地 DuckDB 文件的打开、挂载、读取和写入分别交付支持/受限/不支持结论及可重复证据，仅开放已验证操作且不修改测试原件。验收：故事 2 场景 3。
- **FR-004**: 系统 MUST 展示表名、字段名与类型、行数、各列空值数和数值列的最小值/最大值/均值。验收：故事 1 场景 1。
- **FR-005**: 系统 MUST 允许分别指定训练和预测查询、目标、任务类型及有序特征，校验两侧特征匹配、目标有效性、空输入和模型规模限制，保留逻辑行顺序、数值与空值含义。验收：故事 1 场景 2 及数据边界用例。
- **FR-006**: 系统 MUST 使用既有共享预测能力，在浏览器内至少提供一个可接受用户数据的已验证回归模型；显示其他模型及任务的真实能力和限制。验收：故事 1 场景 3、故事 3 场景 2。
- **FR-007**: 系统 MUST 将完整有效的预测注册为可查询表，保存逐行身份和实验元数据，失败、取消或过期结果不得替换已有成功结果。验收：故事 1 场景 3、故事 3 场景 5 和结果异常用例。
- **FR-008**: 系统 MUST 支持查询结果的 CSV、Parquet、Arrow 导出，并随结果保留可复现实验所需的数据版本、训练/预测 SQL、特征顺序、目标、任务、模型及权重版本、运行身份、执行方式和耗时。验收：故事 1 场景 4。
- **FR-009**: 系统 MUST 在数据处理和模型运行期间保持界面可操作，提供阶段状态、可获取的进度与资源信息、耗时及取消入口；取消请求被确认不等于底层计算已即时终止。验收：故事 3 场景 1。
- **FR-010**: 系统 MUST 缓存可复用的数据快照与模型内容，校验完整性及版本，明确刷新、失效、存储失败和缓存丢失的行为，不以更新后的内容冒充旧实验数据。验收：故事 3 场景 3、4。
- **FR-011**: 系统 MUST 对来源访问、查询、模型能力、存储和执行失败提供具体错误与可执行的恢复建议，保留用户配置及其他可用数据；禁止静默更换模型或远端推理。验收：故事 2 场景 4、故事 3 场景 2、4、5。
- **FR-012**: 本期 MUST 实际交付一份固定版本的小型测试数据包，包含正常样本及隔离的异常变体、来源/许可、字段/单位/时间含义、行数、文件大小、内容校验值和版本说明，不只提供下载链接或准备数据的计划。验收：故事 4 场景 1、2、4。
- **FR-013**: 数据包 MUST 提供正常样本的 CSV、Parquet、Arrow 及 DuckDB 文件副本，并提供等价 JSON 数据接口样本；明确格式类型解释、预期记录数、空值数、范围与汇总，以及训练、预测、结果关联和导出的示例 SQL。验收：故事 2 场景 1–3、故事 4 场景 2、3。
- **FR-014**: 数据包 MUST 包含正常回归路径及故事 4 场景 4 的八类边界输入，记录各自预期行为；重复业务键和重排不得被当作天然非法输入。验收：故事 4 场景 4。
- **FR-015**: 数据包 MUST 将训练目标、预测输入和留出的预测真值清晰区分，说明时间切分、字段可用时间，并为至少一个已验证模型提供独立参考预测、版本、生成依据及目标单位误差预算。验收：故事 4 场景 2、5。
- **FR-016**: 数据包 MUST 附带“用例—输入—操作—预期结果”索引，覆盖导入、结构浏览、SQL、特征适配、预测、结果关联、导出往返、缓存复用及失败提示；数据内容变化必须更新版本与预期结果。验收：故事 4 全部场景。

### Key Entities *(include if feature involves data)*

- **数据源与快照**：本地文件或远端来源、内容身份、版本、取得时间、字段结构、记录数及缓存状态；实验绑定实际使用的快照。
- **查询与特征选择**：训练/预测查询、参数、目标与有序特征，以及预览和验证状态。
- **实验**：绑定数据、查询、任务、模型交付版本及运行配置的一次可复现实验定义。
- **运行与预测表**：阶段、状态、耗时、实际执行方式、逐行输入身份和预测输出，关联所属实验。
- **测试数据包**：固定版本的正常数据、多格式等价副本、异常变体、独立参考、说明及用例索引。
- **能力记录**：数据入口、模型、任务及当前环境的已验证支持状态、限制、错误和恢复建议。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 测试者仅按随附说明即可完成“导入 → 检查 → 定义训练/预测 → 运行 → 查询 → 导出再导入”完整流程；32 个预测行均有有限结果且关联错误为零。
- **SC-002**: 正常样本的所有格式副本在约定类型解释下，记录数、空值数、字段含义及预期汇总 100% 一致；三种导出格式往返后行身份与数值含义全部保留。
- **SC-003**: 数据包包含 256 个训练行、32 个预测行、4 个数值特征及八类边界输入；文件合计不超过 10 MiB（不含模型权重），所有文件校验通过，全部用例都有明确预期结果。
- **SC-004**: 固定版本正常样本的全部预测符合交付前已记录的独立参考误差预算；无未来信息或预测目标真值作为特征，所有训练时间早于预测时间。
- **SC-005**: 在声明的验收设备上，数据加载、长查询和预测期间各进行 10 次面板切换或取消操作，每次操作均在 1 秒内获得界面反馈；报告记录设备、数据规模及各阶段耗时。
- **SC-006**: 相同版本完整缓存的模型与数据重新打开时，其内容重新下载次数为零；损坏、丢失和存储不足用例均得到明确恢复提示，错误缓存被当作有效输入的次数为零。
- **SC-007**: 数据入口与模型能力记录覆盖本期全部入口及可见模型；不支持操作和失败用例均显示具体原因，不存在静默更换模型、错误覆盖成功结果或未经确认覆盖同名表。

## Assumptions

- 范围来源为 [roadmap.md 的 Phase 1](../../roadmap.md)，交付可操作的通用工作台及测试数据包。React、TypeScript、Vite、DuckDB-WASM、数据/模型 worker 和 Arrow/TypedArray 适配是路线图已有技术约束，由后续 plan 落实；本规格定义其应实现的可观察行为。
- 复用 [001 Common View Runtime](../001-common-view-runtime/spec.md) 的共享预测契约，本期不重新定义其数值准确性与缓存身份规则。默认以已支持用户数据训练上下文的 TabPFN 3.5 数值回归贯通闭环；TabICL v2 等模型只开放已有验证能力。
- 默认测试数据采用确定性的合成小时级天气与用电需求数据，包含时间、业务键、4 个数值特征及回归目标；清楚标注为合成测试数据，不冒充真实观测或真实预测能力证据。实际文件、固定生成规则和参考输出在本期实施中交付，本次 specify 仅形成需求。
- 正常样本不含异常值；异常情况放入独立变体。时间与天气变量可供后续情景测试复用，但本期不承诺真实案例、滑块编辑、实时数据管线、设备调度或因果分析。
- 远端入口通过可控测试来源验证，覆盖访问成功与失败；数据包本身可离线取得，但首次模型下载和未缓存远端内容仍可能需要网络。
- 支持目标为已有验证的桌面浏览器。分类、多成员模型、尚未验证的模型能力、移动端性能、任意远端数据库直连、账户协作及云端推理不在本期范围。
- DuckDB 文件具体能力以验证结果为准，不预先承诺读写全部可用；每项受限结论必须有证据和面向用户的提示。
- 浏览器缓存可能被清理，实验元数据和导出不等于永久备份；恢复缺失的本地数据可能需要用户重新选择原文件。
- 当前 constitution 仍是未填写模板，不把其示例原则当作已采纳的项目约束。
