# Dataset 驱动的预测工作台

日期：2026-09-20

状态：用户已确认对话中的设计方向；本文待审阅。尚未开始本轮产品代码修改。

## 目标与范围

将现有工作台统一为标准机器学习流程：数据源 → Dataset → Train / Test → 目标与特征 → 模型 → Test 预测结果。沿用现有浏览器内 DuckDB、TabPFN 3.5、Worker 推理、IndexedDB 存储和深色界面，不引入服务器数据处理。

本次同时修正信息组织和实际数据语义，不以隐藏旧控件代替功能实现。保留真实 mean、q25、q75 推理与数值对齐能力。q25–q75 表示预测分布的四分位区间，不称为置信区间。

## 方案选择

采用显式物化 Dataset。直接在两个输入 SQL 中重复 JOIN 虽然改动较少，但难以解释输入来源，也容易产生不一致；仅创建懒执行视图则不能固定一次实验的数据版本。物化 Dataset 能让切分共享稳定的数据、顺序和版本。

本次一个工作台维护一个活动 Dataset，可由多个数据源构建；不扩展为多个 Dataset 的管理平台。不增加新模型的推理实现。

## 数据源与 Dataset

- 左侧只显示导入的数据源，不把 Train、Test 或预测结果自动注册为数据源。
- 添加数据源提供本地文件、现有远程导入入口和示例数据；示例一次加载完整源，不再分别加载训练和预测数据。
- 接通 CSV、JSON、Parquet、Arrow 导入。其他尚未接通的格式明确禁用并解释，不保留可提交后必然失败的选项。
- 数据源名称使用安全标识符；拒绝内部保留名。覆盖同名源只确认一次。
- 单源生成默认 Dataset SQL；多源允许通过 SQL JOIN。展示可引用的源名、列名及 JOIN 示例，不增加图形化 JOIN 编辑器。
- “生成 Dataset”执行只读 SQL 并物化完整结果。保留列类型、行序和快照版本，展示行列数与折叠预览。重复列名要求用户通过别名消除，避免静默丢列。
- 源改变或 Dataset SQL 编辑后，标记 Dataset 待更新，阻止使用旧版本进行新推理；重新生成后使旧切分失效。

## Train / Test 切分

- 在同一区域使用 Train / Test 页签，每个页签包含自己的 SQL、实际输入行数和折叠 Data preview。
- SQL 针对活动 Dataset 执行；选择的列、WHERE、ORDER BY、LIMIT 都影响真实模型输入。预览最多显示 200 行，不截断模型数据。
- 默认比例为前 80% Train / 后 20% Test。用户可选择排序列；时间列可作为默认排序列，无适合列时明确采用 Dataset 物化行序。相同排序值以稳定行标识打破平局。
- 另一预设为时间列和明确切分点：Train `< cutoff`，Test `>= cutoff`。空时间值不静默分配，展示排除数量。两种预设均生成可查看、可编辑的 SQL。
- Train 取 floor(N × 0.8)，其余为 Test；不足以形成非空两组时提示用户，不自动复制行。
- 内部行标识不作为模型特征。预设切分可验证无重叠；自定义 SQL 在保留可追踪行标识时检查重叠，否则明确提示无法自动验证，而不是声称不存在重叠。
- 将“检查输入”改为“执行 Train / Test SQL”，执行后展示真实行数及列选择。无数据、SQL 错误、缺少列等在对应区域反馈。

## 目标与特征

- 使用可访问的单选 tag 选择一个数值回归目标，多选 tag 选择输入特征；选中状态不只依靠颜色。
- 候选特征来自 Train / Test 共有且模型支持的数值列，默认排除目标及内部标识列。空值按现有模型输入策略处理；非法目标值明确报错。
- Test 可包含同名目标作为真值，但该列绝不进入模型输入。没有真值仍可预测；部分真值缺失时曲线断开，不补零。
- SQL 改变后列选择必须重新校验。用户主动取消全部特征时不自动重新全选，运行按钮解释不可运行原因。

## 模型与执行

- 主区域固定显示模型选择、权重精度、计算后端及模型状态，不藏在高级设置中。
- TabPFN 3.5 是当前可用模型；其他模型只有在已有产品入口需要保留时展示，并禁用且说明限制。
- 区分未检查缓存、需下载、下载中、已缓存、加载中、已加载和失败。仅在真实缓存或 Worker 状态支持时声称已下载/已加载，不能由历史点击记录推断。
- 精度明确解释 fp32 与 fp16 存储方案，不将 fp16 存储误称为全流程 fp16 计算。
- 运行冻结 Dataset、SQL、目标、特征与模型配置。失败或取消不发布部分结果；运行状态和重试入口可见。

## Test 结果与交互

- 预测是 Test 行的附加输出，不创建独立的可选数据源。严格依据实际输入行序对应 mean、q25、q75 与可选真值，不使用可能重复的业务键拼接。
- 保留 Test 原始列，并将预测输出放在独立命名空间或使用明确、无冲突的导出列名，防止覆盖原数据。
- 结果默认显示 mean 曲线、q25–q75 区间、有值时显示真值；Test 明细表默认折叠。
- 鼠标悬停、触摸及键盘定位数据点时显示横轴值、mean、q25、q75、真值；缺失数据明确表示。保持纵轴、图例、单行结果和响应式布局可用。
- 修改上游配置后保留最后成功结果，但显著标记“来自上次运行”；成功运行后原子替换，失败不把旧结果标为新结果。

## 页面层级（impeccable）

使用 Operate 模式，保留既有深色、克制的视觉身份。

1. 左侧：数据源、添加入口、保存/导出实验、导出 Test 预测、已保存实验。
2. 主区 Dataset：来源与构建 SQL、生成操作、行列摘要、折叠预览。
3. 主区 Train / Test：切分预设、页签内 SQL 和预览、目标/特征 tags。
4. 主区模型：模型、精度、后端、状态及运行操作。
5. 主区结果：交互曲线、运行摘要、折叠 Test 明细。

移除底部与输入脱节的查询浏览区。次要诊断和能力说明折叠；核心操作保持可见。小屏侧栏堆叠，表格局部横向滚动，页面整体不溢出。保持键盘焦点、标签、错误播报和忙碌禁用状态。

## 保存、恢复与导出

- 实验保存数据源快照绑定、Dataset SQL 和物化快照、两个切分 SQL、排序/切分配置、目标/特征、横轴、模型与精度/后端。
- 新字段采用版本化或可选兼容策略。旧实验不默默改写为 80/20；能恢复的原始 SQL 和源继续保留，无法迁移的部分明确要求重新生成 Dataset。
- 导出预测 CSV 为当前成功运行的 Test 行及附加输出，保持列名、引号、空值和行序正确。
- 导出实验为 JSON 配置及快照引用，不含权重、凭据或完整源数据；界面明确该文件不是跨设备可独立恢复的数据包。

## 代码边界

- 将 Dataset 构建、稳定切分和配置验证从 App 控制器抽为可测试模块。
- 数据源解码复用 file-codecs 和 DuckDB 文件注册能力，不另写 CSV/Parquet 解析器。
- App 负责事件与状态协调，workbench-view 负责信息结构，prediction-chart 负责绘图和交互绑定。
- 扩展实验存储定义及恢复逻辑；保持现有 Worker 推理和分位数算法不变。
- 仅改动本请求涉及的工作台与测试，不整理其他未提交修改。

## 验收标准

1. 一个示例入口生成 Dataset，默认确定性 80/20 切分，Train/Test 均非空且不重叠。
2. 两个源通过 JOIN 生成 Dataset；Parquet 和 Arrow 真正导入成功，错误格式给出有效提示。
3. 时间边界相等的行只进入 Test；相同时间值、空时间值、小数据量都有测试。
4. SQL 的 LIMIT、列选择和排序影响真实输入；超过 200 行的输入不因预览上限被截断。
5. 目标 tag 单选、特征 tag 多选，目标不泄漏；选空、改 SQL、缺列状态可解释。
6. 真实 WASM 推理输出有限的 mean 和有序 q25/q75，Test 行对齐，部分/无真值均可展示。
7. 图表 hover、触摸/键盘交互显示实际值；原 Test 列名与输出名称冲突不丢数据。
8. 保存刷新恢复 Dataset 与配置；修改上游、失败、取消不会误显示过期结果为新结果。
9. 模型缓存/加载状态有实际证据，精度切换使模型状态正确失效；两个导出动作可用。
10. 更新已有浏览器测试选择器与语义；运行单元/契约测试、应用构建、真实推理 E2E。保持独立官方参考数值测试，不将不同预处理下的 UI 结果冒充同配置对齐。
11. 完成一轮桌面/移动端批量视觉检查及 impeccable 检测，集中修正发现的问题，最多一轮确认。报告未通过或环境无法验证的项目，不宣称全部完成。
